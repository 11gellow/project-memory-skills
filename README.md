# project-memory

**版本：v0.2**

为轻量级至中型 Vibe Coding 项目提供规划、进度与长期技术决策记忆。通过项目内的 Markdown 文档，帮助 Codex 在上下文压缩、会话重启或切换项目后恢复工作，减少规划偏移、进度遗忘和决策依据丢失。

以 Markdown 指令和模板为主，不依赖 MCP、数据库、外部服务或专用脚本。

支持长期开发中的新需求、计划调整和按需归档；原始规划可以依据新的明确授权持续演进。

## 快速开始

在需要管理的项目中，与 Codex 对话调用：

```text
$project-memory init
```

已有实现，需要恢复工作状态或同步进度：

```text
$project-memory sync
```

检查实现、任务与历史规划是否一致：

```text
$project-memory audit
```

整理已经结束的任务和过时状态，保留证据与历史入口：

```text
$project-memory archive
```

这些是 Codex 对话中的 Skill 调用，不是终端命令。可以附加本次目标和约束：

```text
$project-memory init
检查现有项目，补齐缺失的管理文档，保留已有规划；无法确认的信息标为待确认。
```

```text
$project-memory sync
恢复当前开发进度，核对最近变更和验收记录；不要开始新的功能开发。
```

```text
$project-memory audit
检查当前实现是否违反架构约束，或与历史技术决策冲突，只报告问题。
```

## 四种工作模式

| 模式 | 主要工作 | 文档修改边界 |
| --- | --- | --- |
| Init | 检查目录、代码、配置、Git 和已有文档，建立项目记忆 | 补齐缺失文件、整合缺失内容，保留原规划与约束 |
| Sync | 恢复进度、整理新需求和任务调整，必要时自动归档 | 按已有授权演进规划，依据真实证据维护状态和决策 |
| Audit | 核对需求、架构、历史决策、任务状态与验证证据 | 默认只报告问题，不修改文件 |
| Archive | 按需归档已结束任务和过时状态 | 先保留并核对历史，再精简原记录、保留索引与引用入口 |

支持自然语言请求；明确要求建立项目记忆、恢复或同步进度、整理需求与计划、归档历史或审计一致性时，可以自动匹配。普通编码任务不会触发完整管理流程。

## 新需求与计划调整

- **想法**：进入候选区，不自动变成已批准需求或启动开发。
- **明确需求**：检查相关旧功能、接口、数据兼容与回归影响，补充任务和验收标准。用户明确要求实现就是该功能的授权，不因最初未规划而阻止，也不重问整个项目。
- **方向调整**：保留对旧范围、任务和技术决策的影响及确认依据；尚未获授权的技术例外或关键歧义保持待确认。

未指定优先级时保留当前任务，新需求进入后续计划；明确要求现在实现时按本轮目标处理，影响其他已承诺交付时再澄清取舍。延期保留恢复条件；取消和替代保留原因与关系，不算作验收完成。恢复工作时会提出具体的下一步建议，建议本身不扩展授权。

例如，在 Codex 对话中输入：

```text
$project-memory sync
新增导出功能，请先整理需求和验收条件，放到当前任务之后，不开始实现。
```

## 长期开发与归档

当已结束任务和重复状态明显影响恢复效率时，Sync 可自动归档；也可显式调用 `archive`。不按开发次数或时间机械归档，没有合适内容就不创建空归档。

默认沿用现有归档约定；没有约定时保存到管理文档目录的 `archive/YYYY-MM-DD-NN.md`。原任务编号、验收证据、取消或替代原因继续保留，TASKS 留历史索引与必要锚点转接。再次执行无新内容时不重复写入。

待处理任务、候选、延期、受阻、验证缺口和未决事项留在活跃文档。v0.2 不搬移 PROJECT、ARCHITECTURE、DECISIONS；日常恢复无需读全部历史，只有追溯或审计时才加载相关归档。Audit 始终只读。

## 项目中的管理文档

缺省结构如下；已有等价文档时，沿用项目原来的路径、语言和组织方式，不创建重复副本。

```text
your-project/
├── AGENTS.md
└── docs/
    ├── PROJECT.md
    ├── ARCHITECTURE.md
    ├── DECISIONS.md
    ├── TASKS.md
    └── STATUS.md
```

实际需要归档时才增加 `docs/archive/`（或项目已有的等价位置），不增加常驻管理文档。

| 文件 | 用途 | 维护方式 |
| --- | --- | --- |
| AGENTS.md | 日常开发规则与上下文恢复入口 | 保持简洁，合并缺失规则 |
| PROJECT.md | 项目目标、需求、范围和稳定约束 | 重大变更须用户确认 |
| ARCHITECTURE.md | 模块职责、依赖关系与关键流程 | 重大变更须用户确认 |
| DECISIONS.md | 重要技术决策、理由和演进历史 | 区分待确认、已确认与已废弃 |
| TASKS.md | 计划任务、状态和验收标准 | 根据真实证据动态更新 |
| STATUS.md | 当前阶段、问题、验证缺口和下一步 | 保持简短、及时同步 |

新会话或上下文压缩后，先读 STATUS 和 TASKS；涉及项目目标、架构或既定选型时，再读取对应文件。日常恢复规则保存在项目 AGENTS 中，不需要每次加载整个 Skill 或全部历史。

## 决策记忆与规划保护

重要决策使用稳定编号，例如 `D-001`，记录名称、状态、背景、最终选择、选择原因、替代方案和未来影响，并保留日期、确认依据及新旧决策关系。

- 仅记录对未来开发有长期影响的选择，不记录琐碎实现细节。
- 当前代码和 Git 提交只能证明实现事实，不能证明用户已经批准该选择。
- 未确认方案标为“待确认”；缺失的历史理由或替代方案写“未记录”，不补造历史。
- 替代已确认决策前须有用户确认；新增决策并关联旧编号，保留旧选择和理由。已有明确授权无需重复确认。
- 发现代码偏离规划时保留差异，不以现有实现反向覆盖原始目标。

详细条目结构见 [文档模板](references/templates.md#decisionsmd)。

## 进度与验证

任务只有在验收标准已有证据支持时才能标为完成。已有代码、部分测试通过或提交成功，均不能直接代表功能验收完成。

Sync 会区分本轮执行、历史记录、未执行和不适用的验证，注明结果及适用范围。缺少环境或仍需人工验收时，保留验证缺口，不把局部通过扩大为兼容性、发布或完整项目验收。

恢复状态或同步文档本身不授权新功能开发；用户同时明确要求实现某项功能时，可在该授权范围内继续。提交、发布或改变系统设置仍遵循其授权范围。没有 Git 仓库时可以基于文件工作，不会自行初始化仓库。

## 安装与文件说明

将整个 `project-memory` 文件夹放入用户级 Codex Skills 目录：优先使用 `$CODEX_HOME/skills`；未设置时使用 `~/.codex/skills`。已有同名 Skill 时先检查内容，避免直接覆盖。

```text
project-memory/
├── SKILL.md
├── README.md
├── agents/
│   └── openai.yaml
└── references/
    ├── templates.md
    └── lifecycle.md
```

- [SKILL.md](SKILL.md)：供 Codex 读取的工作流入口与维护规则。
- [references/templates.md](references/templates.md)：初始化或补充文档时按需使用的六类模板。
- [references/lifecycle.md](references/lifecycle.md)：新需求、计划调整与归档细则，仅在相关场景读取。
- [agents/openai.yaml](agents/openai.yaml)：显示名称和简述，保持默认允许自动选择。
- 本 README：面向使用者的说明，不作为每次开发的常驻上下文。

校验方式为 `skill-creator` 的 `quick_validate.py`，并使用隔离合成样例检查工作流行为；具体执行结果以对应更新的验证报告为准。这些检查不代表被管理项目的业务功能已经验收。
