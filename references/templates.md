# 项目管理文档模板

仅读取并使用当前需要的章节。保留项目原有路径、语言、任务编号和结构；下列占位内容必须替换为事实或明确的“待确认 / 未记录 / 未执行”。无对应内容时保持简短，不为了填表编造历史。

## AGENTS.md

只合并缺失规则；已有等价约定不重复添加。下面路径为缺省值，使用时替换为实际位置。

```markdown
## 项目记忆与开发规则

- 新会话或上下文压缩后，先读 [STATUS](docs/STATUS.md) 与 [TASKS](docs/TASKS.md)，确认当前任务和验证缺口。
- 涉及目标、需求、范围或技术栈时读 [PROJECT](docs/PROJECT.md)；涉及模块/依赖时读 [ARCHITECTURE](docs/ARCHITECTURE.md)；涉及既定选型或重大变更时检查 [DECISIONS](docs/DECISIONS.md)。按需加载，不必每次读全量文档。
- 核对相关代码和 Git 状态；不确定时重读文件，不凭模糊记忆实施。实现事实不自动取代已确认规划。
- PROJECT、ARCHITECTURE 的重大变更及重要决策替代须先获用户确认；已有明确授权无需重复询问。未知选择标待确认，不视为实施授权。
- 完成开发后按验收标准验证，同步 TASKS、STATUS 和必要决策；未验证不标完成，未执行/失败/受阻写明原因和缺口。
- 重大技术决策记录背景、选择、原因、替代方案和长期影响；保留已确认决策及其变更历史。
- 新想法只记为候选；明确要求的新需求检查相关影响后纳入计划，已有授权不重复确认。调整任务保留原因和替代关系。
- 历史妨碍恢复时可按需归档已结束记录，保留证据与索引；当前任务、验证缺口和未决事项继续留在活跃文档。
```

```markdown
- 已确认技术栈、平台及其他约束：待确认。

重大规划变更须经用户确认；实际进度见 [STATUS](STATUS.md)，任务见 [TASKS](TASKS.md)。
```

## DECISIONS.md

新文件可以只有标题与规则，没有真实候选项时不要创建示例决策。每项按下列结构记录；未知字段写“未记录”，保留实际证据，不补造原因。待确认条目不构成实施授权。

```markdown
# 重要技术决策

仅记录对后续开发有长期影响的选择。状态为待确认、已确认或已废弃；稳定编号不重用，替代时保留历史并相互链接。

## D-001｜决策名称

- 状态：待确认
- 日期：实际记录日期；历史决策日期未知则注明未知
- 背景与需要解决的问题：待确认
- 最终选择：未确认；候选：待确认
- 选择原因：未记录
- 曾考虑的替代方案：未记录
- 对未来开发的影响：待确认
- 确认依据：未记录；注明可追溯的授权或历史记录位置
- 新旧决策关系：无 / 拟替代 D-xxx / 替代 D-xxx / 被 D-yyy 替代
- 相关架构或实现事实：按需链接，不复制架构全文
```

## TASKS.md

已有状态约定优先。新项目使用未勾选配合候选、待开始、待确认、进行中、待验证、受阻、延期、取消、被替代；勾选仅表示有验收证据的已完成。取消/被替代的未完成项不勾选。历史已完成后被新功能替代，保留原验收事实并记录当前替代关系。没有明确需求时只记录已授权的管理任务及必要澄清，不虚构产品任务。

沿用原分组；必要时才用“当前 / 后续 / 候选”区分优先级。归档后保留历史索引及被引用锚点，不强制为小项目创建空分区。

```markdown
# 开发任务

> 更新日期：实际日期。完成状态必须有验收证据。

- [ ] T-001｜任务名称
  - 目标：已授权目标或明确标注待确认的候选。
  - 需求来源：实际日期及用户要求/记录位置；仅 AI 建议须注明。
  - 状态：待确认
  - 验收标准：可检查的结果，未知则待确认。
  - 验证证据：未执行；执行后记录方式/命令、日期、结果和范围。
  - 剩余工作/阻碍及解除条件：按实际填写。
  - 计划调整：有调整时写日期、原因、授权依据及恢复条件或替代任务编号，无调整则省略。

当前状态与下一步见 [STATUS](STATUS.md)。
```

按需归档后的索引示例（替换为真实路径、状态与编号）：

```markdown
## 历史任务索引

- T-001｜任务名称｜已完成/取消/被替代｜[完整记录](archive/YYYY-MM-DD-NN.md#t-001)
```

归档目标使用显式锚点或核对后的标题锚点；原来被引用的任务标题/ID 在原位置保留短转接，不以索引示例取代已有锚点。

## STATUS.md

这是当前快照，避免将全部日志堆积于此。历史结果注明来源和适用范围，不冒充本轮执行；简短引用任务或验收记录。

```markdown
# 当前状态

> 更新日期：实际日期。恢复工作先读本文件与 [TASKS](TASKS.md)。

## 当前阶段与任务
- 基于实际证据填写；未知则待确认。

## 最近关键完成
- 仅列有验收证据的结果；没有则写“暂无已验证完成项”。

## 验证结果与缺口
- 本轮执行：未执行；原因按实际填写。
- 历史证据：未记录；引用后注明日期和范围。
- 尚未验证：按实际填写，不把部分通过推定为全部完成。

## 问题与待确认决策
- 按实际填写；涉及长期选择时链接 [DECISIONS](DECISIONS.md)。

## 下一步
1. 基于当前依赖、风险与验证缺口提出具体下一步及理由，注明已有授权；需要确认时说明具体待决事项。建议本身不构成实施授权。
```

## 按需归档批次

仅在实际归档时创建；文件名与写入核对流程见 [lifecycle.md](lifecycle.md)。以下是归档元信息和记录示例，不要用占位示例替代待迁移的原文。

```markdown
# 历史归档：实际日期与批次

- 归档日期：实际日期
- 来源文件：TASKS.md / STATUS.md 的实际路径
- 范围与原因：本批次任务编号及过时状态范围，为什么不再影响当前工作

<a id="t-001"></a>
## T-001｜原标题

保留原状态、目标、需求来源、验收标准、验证证据、调整原因、替代关系和必要上下文。调整迁移后的相对链接；未知内容标明未记录，不编造。

## 历史状态记录

保留原记录日期和适用范围；仍有效的问题与验证缺口留在当前 STATUS。
```
